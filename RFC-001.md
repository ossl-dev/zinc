# RFC-001: Zinc is a universal shared memory runtime

## The original idea

I wanted fast communication between JavaScript runtimes on the same machine. The usual options, Unix sockets, HTTP, WebSockets, all felt wasteful. On the same machine, why go through the kernel's network stack?

So I built Zinc v1: a lock-free ring buffer in Zig, mapped into shared memory via `shm_open` + `mmap`, with FFI adapters for Bun, Deno, and Node. It worked, but it had architectural problems: the ring was fighting itself for bidirectional comms, the "zero-copy" claim was dishonest (serialization + two `memcpy`s), and the latency floor was JavaScript's `setInterval` (~1ms).

The real insight was hiding in plain sight: the `mmap` was the valuable primitive, not the ring buffer.

## What was broken in v1

- **Zig-only core.** Adding Python/Go/C++ adapters meant reimplementing logic. No single source of truth.
- **Ring buffer as transport.** 4KB slot limit, no streaming, no backpressure. The data path was: object → binary encode → memcpy into ring → memcpy out of ring → decode → new object. Not zero-copy.
- **macOS bugs.** `std.os.linux.getpid()` called on Darwin returned garbage. Every message had a corrupt sender PID.
- **Memory leaks.** Node addon allocated a 4KB `Vec` on every `poll()` tick, even with an empty ring.
- **JavaScript polling.** Minimum `setInterval` resolution of ~1ms in Node made the native speed irrelevant.

## What Zinc v2 is

Zinc v2 is a cross-language shared memory library. Rust core, C ABI surface, adapters for 7+ languages. One `mmap`'d region, zero copies, no serialization, all languages read/write the same physical pages.

```rust
// Rust
let region = SharedRegion::create("my-data", 16384)?;
let ptr = region.as_ptr();
unsafe { std::ptr::write(ptr as *mut f32, 42.0); }
region.notify();
```

```python
# Python, same physical memory, zero copies
r = SharedRegion.open("my-data")
if not r.wait(1000):
    raise TimeoutError("writer did not publish data")
arr = r.as_numpy(dtype=np.float32)
print(arr[0])  # 42.0
```

```go
// Go, same physical memory, zero copies
r, _ := zinc.Open("my-data")
if !r.Wait(1000) { panic("writer did not publish data") }
data := r.Bytes()
val := *(*float32)(unsafe.Pointer(&data[0]))
```

Every language gets a zero-copy view of the same bytes. No serialization. No copies. Just memory.

The creator must remain alive until readers open it. Notifications publish writes but do not prevent later concurrent writes; repeated updates need an application protocol or atomic data.

## Architecture

```
┌──────────────────────────────────────┐
│  Python  │  Go  │  C++  │ Java │ C#  │  ← Adapters (thin FFI wrappers)
│  (cffi)  │(cgo) │(hpp)  │(JNA) │(P/Invoke)
├──────────────────────────────────────┤
│        include/zinc.h                │  ← C ABI (opaque void* handles)
│   zinc_create / zinc_open / ...      │
├──────────────────────────────────────┤
│        Rust core (cdylib)            │  ← Single source of truth
│   SharedRegion / Ring / Sync         │
├──────────────────────────────────────┤
│   POSIX shm_open + mmap + futex      │  ← Platform layer
│   (Linux, macOS)                     │
└──────────────────────────────────────┘
```

The C ABI exposes nine functions. FFI adapters load the same compiled `.dylib`/`.so`; Rust and Node use the crate directly. The core owns mapping and notification behavior. Adapters translate types and errors and manage their views.

## What this enables

- **ML pipelines.** Python writes model weights as Float32Arrays. Bun serves them via HTTP. No separate copy between the producer and consumer mappings.
- **Video processing.** Go writes frames at 60fps into shared memory. Node reads them directly. No serialization.
- **Game engines.** Physics in C++, rendering in another process. World state lives in typed arrays backed by shared memory.
- **Polyglot systems.** Any language that can call C can participate. The memory is the API.

## What's next
