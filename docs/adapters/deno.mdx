The Deno adapter uses `Deno.dlopen` to load the Zinc shared library. Like the Bun adapter, no native addon is needed. The FFI bindings are defined at runtime in TypeScript.

## Installation

Build the core from a [source checkout](/getting-started/installation), then set up the adapter:

```bash
# Import ./adapters/deno/src/mod.ts with the adapters/deno/deno.json import map
```

## SharedRegion

```typescript
import { SharedRegion } from "./adapters/deno/src/mod.ts";
```

### create

```typescript
const region = SharedRegion.create("my-data", 16384);
```

Creates a new region. Throws on failure.

### open

```typescript
const region = SharedRegion.open("my-data");
```

Opens an existing region.

### buffer

Returns a `Uint8Array` backed by the shared memory mapping. Uses `Deno.UnsafePointerView.getArrayBuffer` for zero-copy access.

```typescript
const buf = region.buffer();
const view = new DataView(buf.buffer);
view.setFloat32(0, 3.14, true);
```

### notify

```typescript
region.notify();
```

### wait

```typescript
const ok = region.wait(1000);
```

Returns `true` on notification, `false` on timeout.

### close

```typescript
region.close();
```

Supports `Symbol.dispose` for `using` declarations:

```typescript
using region = SharedRegion.open("my-data");
const buf = region.buffer();
```

## Complete example

```typescript
import { SharedRegion } from "./adapters/deno/src/mod.ts";

// Writer
const w = SharedRegion.create("deno-channel", 16384);
const buf = w.buffer();
const view = new DataView(buf.buffer);
view.setFloat64(0, 2.71828, true);
w.notify();

setTimeout(() => w.close(), 5000);

// Reader (separate process)
const r = SharedRegion.open("deno-channel");
if (r.wait(3000)) {
    const data = r.buffer();
    const v = new DataView(data.buffer);
    console.log(v.getFloat64(0, true)); // 2.71828
}
r.close();
```

## Permissions

The adapter requires these Deno permissions:

- `--allow-ffi` to call `Deno.dlopen`
- `--allow-read` to locate the shared library

Without these, the import will fail with a permission error.

## FFI details

The loader resolves `target/release/libzinc_core.{so,dylib}` relative to the source checkout. Handles use Deno's opaque `PointerValue` objects. The adapter targets Deno 2 and requires `--unstable-ffi --allow-ffi --allow-read`.

Keep the region open while any returned view is in use. `close()` is idempotent and later operations on the region throw. `tryWait()` consumes a pending notification without blocking. Timeouts must be integers between 0 and `2^32 - 1` milliseconds.
